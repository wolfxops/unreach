Dynamic agentic workflow

unreach workflow / MCP unreach.workflow turns findings into an ordered checklist tailored to the repository's languages and frameworks. It is data an agent executes, not prose it interprets.

Shape

{
  "auto_delete": false,
  "profile": { "primary": "py", "frameworks": ["fastapi", "pytest"], "monorepo": false, ... },
  "policy": { "block_threshold": 0.85, "warn_threshold": 0.55,
              "delete_requires": "explicit user approval after validation steps pass" },
  "selected_findings": ["orphan_file:pkg/orphan.py", "unused_export:pkg/exports.py:dead_symbol"],
  "steps": [
    { "id": "ctx-01",    "phase": "verify",   "action": "Read only the files named in this workflow...", "budget_hint": "..." },
    { "id": "verify-02", "phase": "verify",   "finding_id": "...", "grep": "pkg.orphan", "read": ["pkg/orphan.py"] },
    { "id": "edit-03",   "phase": "edit",     "finding_id": "...", "action": "If verified: propose deleting ... Do not delete without user approval." },
    { "id": "validate-06","phase": "validate","command": "python -c \"import pkg\"" },
    { "id": "validate-07","phase": "validate","command": "pytest -q" },
    { "id": "validate-08","phase": "validate","tool": "unreach.scan" },
    { "id": "mem-09",    "phase": "remember", "tool": "unreach.remember" }
  ]
}

How it adapts

DetectedWorkflow changes
PythonImport-check touched packages with python -c "import pkg"; run pytest; run mypy/pyright if configured in pyproject.toml.
Python + framework (Django, Flask, FastAPI, Celery, SQLAlchemy, Click, pytest)Adds a verify step to check framework wiring (INSTALLED_APPS, router includes, autodiscover, entry points) and to confirm the symbol is not registered by a decorator.
TypeScript / JavaScriptReads package.json main/exports/bin and tsconfig.json; runs npx tsc --noEmit when TypeScript is a dependency; runs vitest or jest if present.
Monorepo (workspaces, pnpm, nx, turbo, nested pyproject)Profile flags monorepo: true so the agent scopes verification to the workspace and checks cross-package imports.
Memory has previous runsNew findings are ordered first. The budget hint tells the agent how many findings were already triaged so it does not re-read them.

Phases

  1. verify — targeted grep and bounded reads (the definition block, the first 40 lines). Never "read the repo".
  2. edit — propose a reviewable patch. Deletion is always proposed, never performed by Unreach.
  3. validate — import check, type check, tests, and a re-scan through unreach.scan.
  4. remember — record keep / false_positive / resolved through unreach.remember so the next session starts from the new baseline.

CLI

unreach workflow [PATH] [--format json|md] [--max 12] [--min-confidence 0.25] [--no-memory]

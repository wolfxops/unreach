Why Unreach is built this way

Use cases and pain points behind every feature. Each row maps a real complaint to the mechanism that answers it.

Use cases

Pain points and the mechanism that answers them

Pain point (observed across knip, vulture, ts-prune users and agent post-mortems)Unreach mechanism
False positives from dynamic imports, getattr, importlib, plugin registries and string-named modules. Engineers stop trusting the tool and disable it. Confidence signals: module_named_in_string_literal, module_named_in_config, repo_uses_dynamic_import, module_getattr_lazy_export lower the score so the finding drops from block to warn/note.
Framework code looks dead: FastAPI routes, Django models/admin/migrations, Celery tasks, pytest fixtures, Click commands are invoked by the framework, never imported. Framework profile in langs.py: entry-file roles, registration decorators, and framework base classes. A decorated route gets framework_registration_decorator −0.60.
Misconfigured entry points make used code look unused (knip's most common issue). Entry points are inferred from package.json main/exports/bin, pyproject.toml scripts, __main__ guards, and framework conventions. Explicit config is optional, not required.
Auto-delete is dangerous. AST-based removal breaks contracts; agents confidently introduce bugs from a tool's false positive. Design law: never delete. unreach.plan and unreach.workflow return ordered steps and require validation (import-check, type check, tests) before a human-approved patch.
Legacy debt blocks adoption; teams need a CI ratchet, not a red build on day one. Memory tracks first/last seen. unreach scan --only-new exits 1 only for new block findings.
Enterprise wants findings in GitHub code scanning and an audit trail. --format sarif with confidence and signals in properties; decisions (keep / false_positive / resolved) with notes and timestamps in .unreach/memory.json.
Agents spend most tokens reading, not writing. Each session re-reads files and re-derives the same graph. Compact MCP packets: full evidence for new findings, one-liners for persisting ones, acknowledged ones omitted. Content-hash parse cache skips unchanged files. Workflow names exact files and grep targets instead of "read the repo".
Tools need network, SDKs, or a model to work at all. Detection is offline and deterministic. The LLM is used only for unreach.explain, over plain OpenAI-compatible HTTP, and only if a key is set.

What Unreach deliberately does not do (v0)

  • No auto-delete, no --fix.
  • No SaaS, no telemetry, no cloud memory. Memory is a local JSON file you can commit or ignore.
  • No five-language promise. Python is first-class; TypeScript/JavaScript is an import-graph heuristic and is capped at warn.
